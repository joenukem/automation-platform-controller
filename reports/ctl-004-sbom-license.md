# CTL-004 — SBOM + license hygiene: DONE

**Status: DONE.** The release image ships a full SBOM and a license manifest, and
the license-hygiene gate passes: every **composed source** (the packages this
project forks/pins/patches) is Apache-2.0, and every copyleft component present
is base-OS aggregation or carries a linking exception.

## License gate (what `build/sbom.sh` enforces)

**PASS.** The gate FAILs only if a composed source is non-Apache, or a **Python**
package is plain/strong copyleft without a known linking exception. Base-OS RPM
copyleft (glibc, coreutils, `alternatives`, `rsyslog`, …) is mere aggregation in
a container image — separate programs, not linked into our Apache code — and is
reported, not failed.

### Copyleft components — why none impose obligations on our distribution
- **Python `uwsgi` 2.0.30 (GPLv2+)** — uWSGI is GPLv2 **with an explicit
  linking/plugin exception** permitting it to serve applications under any
  license. It is awx's WSGI server (upstream awx ships it too). The exception is
  precisely for this use. → allowed by the gate.
- **Python `libcomps` 0.1.18 (GPLv2+)** — a binding in the dnf/rpm tooling stack
  present because the image carries `dnf`/`podman`; not imported by awx
  application code. Base-OS aggregation.
- **Base-OS RPMs** (`alternatives` GPL-2.0-only, `rsyslog` GPL-3.0-or-later as a
  separate daemon process, `ca-certificates` MIT-portion, glibc's mixed tree,
  etc.) — standard distro components every centos:stream9 container carries;
  aggregated, not statically combined with our Apache code.

## Rebase obligation

Re-run `build/sbom.sh <release-tag>` at every release and **diff the SBOM against
the prior release's** to catch newly-introduced vulnerable or copyleft transitive
deps (STEWARDSHIP.md CVE watch). A new Python copyleft dep without an exception
fails the gate by design.
